The Acoustic Field
Multi-dimensional session blending

Music isn't a category. It's a position in a continuous space. Drag the parameters — the field blends in real-time. "Jazz + dreamlike + folk" is coordinates, not a label.

The data model
Every track gets an AcousticField object — five floats in [0,1] plus BPM. This is computed from audio features (Essentia / LLM-derived), not manually tagged.

The six session palettes are not categories. They are basis vectors in this space. A track's visual is the weighted combination of all six. 
type AcousticField = {
  energy:     number // 0–1
  warmth:     number // 0–1
  density:    number // 0–1
  organicity: number // 0–1
  sacred:     number // 0–1
  bpm:        number // 40–200
}
Params → session weights
Each session palette is a function of the acoustic parameters. Weights are normalised so they sum to 1. The blend uses screen composite mode — intersections are luminous, not muddy. 
function toWeights(p) {
  const w = {
    jazz:
      p.warmth*.7 +
      (1-p.energy)*.3,
    electronic:
      (1-p.warmth)*p.energy,
    ambient:
      (1-p.energy)*
      (1-p.density),
    folk:
      p.organicity*
      p.warmth*
      (1-p.sacred),
    sacred:
      p.sacred,
    energy:
      p.energy*
      (1-p.warmth),
  }
  // normalise
  const sum = 
    Object.values(w)
    .reduce((a,b)=>a+b,0)
  return Object
    .fromEntries(
      Object.entries(w)
      .map(([k,v])=>
        [k,v/sum]))
}
Rendering + open questions
Each session algorithm runs into its own offscreen canvas. The main canvas composites them in weight order using globalCompositeOperation = 'screen'. This gives luminous intersections — the visual equivalent of the iridescent wave.

Open: should the blend be fully real-time (canvas), or pre-rendered per track and cached? For the loading screen / map view, real-time is right. For the library, cached textures per track makes more sense.
