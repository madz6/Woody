Woody · Product Roadmap · 2025–2026

Build the engine.
Then the platform.

The recommendation engine is the product. The community is the amplifier. Build in that order.

The thesis: Woody is a Letterboxd for music — but only if the underlying product is satisfying to use alone, before the social layer exists. The acoustic recommendation engine has to work so well that a single user with zero friends gets value on day one. Community scales what already works. It doesn't rescue what doesn't.
The job
Find music that fits a feeling, not a genre
Users describe an acoustic intent — a feeling, a moment, a state — and Woody surfaces tracks that occupy that coordinate in acoustic space. Not "jazz" but "slow, warm, something that hasn't resolved yet."
The wedge
DJ sets and mix culture, first
The largest underserved community in music curation. Boiler Room regulars, mix archivists, DJ obsessives. Acute pain, no good tooling, massive public reach. They arrive for utility and stay for identity.
The moat
Your taste history as irreplaceable data
Like Last.fm's scrobbling but acoustic. The longer you use Woody, the more irreplaceable your territory map becomes. Switching cost is identity, not convenience.
Phase 01
Now → 3 months
Acoustic Engine
Moat at this phase
Acoustic intent parsing. Nobody else maps natural language → acoustic coordinates → track recommendations. This is the technical differentiation.
Core engine — the product that earns day-one value
Acoustic analysis pipeline
Ingest tracks → extract energy, warmth, density, organicity, structure as continuous floats. Use Spotify Audio Features API as baseline; layer custom analysis on top for the dimensions Spotify doesn't expose (sacred/structure, exact warmth mapping).
moat
Intent → acoustic coordinate parser
LLM maps natural language intent ("late night drive, something unresolved") to acoustic coordinates. The quality of this mapping IS the product. Needs a training set of intent descriptions paired with acoustic positions — build this by hand first.
moat
Recommendation algorithm
Nearest-neighbour search in acoustic space, weighted by personal territory. Not collaborative filtering — acoustic distance to intent coordinate + personal calibration from SavePoints. Surfaces tracks you've never heard that sit in the exact right acoustic zone.
moat
SavePoint data model
Track + acoustic coordinate + intent description + timestamp + emotional annotation. This is the training signal for personal calibration. Every SavePoint makes future recommendations more precise.
core
Personal territory map (private)
Your listening history as acoustic coordinates. The map grows as you use the product. Private for now — the social layer comes later. But the data model should be built for eventual sharing.
core
Web app — the surface
Intent input → acoustic field → results
The core flow. Type intent, see the acoustic field shift to that coordinate, results surface from that zone. The acoustic field IS the search UI — not a visualisation added on top.
core
Spotify integration — listen + add to library
You find it on Woody, you play it in Spotify. No catalog licensing required. Not a streaming app — a discovery layer. The Spotify add-to-playlist CTA is how Woody creates real value without owning the playback.
core
Real-time audio analysis (Web Audio API)
The acoustic field responds to audio playing in the browser. Already built as v3 prototype. Integrate into main web app flow so the field shifts with what you're actually listening to.
core
Load-bearing assumption
The intent parser is good enough that a first-time user describes something and gets back a track they hadn't heard but immediately recognise as right. If this doesn't happen in the first session, the product hasn't earned retention.
Kill condition
If after 3 months of iteration, fewer than 60% of test users SavePoint a track from their first session — the recommendation quality isn't working. Revisit the acoustic analysis approach before building anything else.
Phase 02
3 → 6 months
DJ / Mix Wedge
Moat at this phase
Mix documentation tooling + acoustic arc visualization. No competitor. The DJ community is the acquisition channel — high taste, high reach, zero tooling.
Mix / set tools — the wedge
Mix session logging
Link a YouTube, Mixcloud, or SoundCloud mix. Extract or manually annotate the tracklist. Each track gets placed as an acoustic coordinate. The result is the acoustic arc of the set — exactly the session timeline we've already designed.
wedge
Acoustic arc visualization (shareable)
The session timeline as an exportable image or live embed. This is the shareable artifact that markets Woody to people who haven't heard of it. A Boiler Room set documented with acoustic arc visualization is content that spreads in mix communities.
wedge
Tracklist parser (YouTube/Mixcloud)
Auto-extract timestamps and track names from set descriptions. Reduces manual annotation to correction, not creation. This is the friction unlock that makes mix logging feel effortless rather than laborious.
core
"Discover from this set" — recommendation from a mix position
Any point in a logged mix becomes a recommendation seed. "Find me more tracks that sit in this moment of the set." The acoustic position of the 47-minute mark of a Boiler Room set becomes a search query.
moat
Load-bearing assumption
DJ/mix community members will log sets in Woody because the acoustic arc visualization is valuable enough to share publicly. If the shareable artifact isn't compelling enough to post, this wedge doesn't work.
Kill condition
If mix arc visualizations aren't being shared externally (posted to Twitter/Instagram/Discord) by Month 5, the wedge community isn't using Woody as a public identity tool. Revisit what the shareable artifact is before building the social layer.
Phase 03
6 → 12 months
Social / Community Layer
Moat at this phase
Social taste graph. Your territory + who you follow forms a discovery network that's irreplaceable. Adjacent territory discovery creates retention that no algorithm can replicate.
Platform features — amplify what already works
Public territory maps + curator profiles
Your acoustic territory as a public identity. Other users can see where your taste lives in acoustic space. Not a playlist list — a map of who you are acoustically. This is the identity layer that creates cultural value.
social
Adjacent territory discovery
Find curators whose acoustic territory overlaps with — or is adjacent to — yours. Not "similar taste" in genre terms. People who occupy the same region of acoustic space. The discovery feed is your neighbourhood.
social
Playlist / territory sharing + embeds
Share an acoustic territory or playlist as a live embed — the acoustic field visualization runs on any page. Substack, personal site, Discord. Every embed is an acquisition touchpoint.
social
Acoustic year-in-review
The anti-Spotify Wrapped. Not "you listened to X songs" — your acoustic arc for the year, showing how your territory shifted, what corners you explored, what you kept returning to. Highly shareable without feeling like advertising.
social
Spotify playlist import → acoustic translation
The "aha moment" for new users. Import an existing playlist → see its acoustic map instantly. No onboarding friction — you arrive with your history already translated into the Woody language.

Phase 04

Pro / Monetization
Moat at this phase
Curator presence as a paid identity good. The platform has cultural cachet — being a serious Woody curator means something. Pros pay to signal seriousness.
Revenue — charge for what curators value
Woody Pro — acoustic analytics
Deep analysis of your listening history and recommendations. Library acoustic fingerprint, territory evolution over time, discovery rate, acoustic diversity score. The data curators want to understand their own taste.
revenue
Pro — embeddable player + acoustic field widget
The acoustic field visualization as an embeddable player on your own site. Like Bandcamp embeds but for your curated acoustic territory. Pro curators get this; it's a visible signal of Woody presence.
revenue
API access — for DJs, journalists, developers
Acoustic analysis and recommendation engine as an API. DJs building setlists, music journalists writing about sonic landscapes, developers building adjacent tools. This is a B2B revenue layer that doesn't compromise the consumer product.
revenue
Native app integration hooks
One-tap "add to Spotify/Apple Music" from any Woody recommendation. Deep linking. Potentially: Woody as the discovery layer that feeds back into the native app you already use. Not replacing the streaming app — sitting above it.

The three bets

What has to be true

These are the assumptions that, if wrong, require a strategy revisit. Know them before you build.

01
The intent parser creates an "uncanny" moment
A first-time user describes a feeling and gets back a track they hadn't heard but immediately recognise as right. Not just good — uncanny. The quality of this moment is the entire product. If it doesn't happen, nothing else matters.
Test: unmoderated first-session with 10 users. Count SavePoints.
02
The acoustic arc visualization is shareable enough to spread
The DJ/mix wedge only works if the acoustic arc visualization is something mix community members want to post publicly. If it's "cool but I wouldn't share it" — the acquisition channel doesn't exist. The artifact has to be identity-expressing, not just informative.
Test: give 20 DJ/mix enthusiasts a finished arc. Count external posts.
03
Curator identity is valuable enough to pay for
Phase 4 requires that having a Woody profile means something culturally. Letterboxd Pro works because being a serious Letterboxd user is an identity marker. Woody needs the same cultural weight before Pro makes sense. This takes time and can't be forced.
Indicator: are users linking Woody profiles publicly without being prompted?
